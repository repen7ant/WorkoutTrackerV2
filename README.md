# Как было?

## 1. Проблемы

- БД хранится в виде файла workouts.db, используется SQLite.
- Только один пользователь (авторизация по паролю: любой, кто знает пароль, имеет доступ к одной и той же бд).
- Бот возвращает только историю выбранного упражнения, нет функции вывода всех тренировок, хотя в бд такая таблица есть.
- Таблица (лог упражнения) при большом количестве подходов смещается и выглядит ужасно.
- У пользователя нет возможности добавить новые упражнения, только использовать заранее добавленые в csv-файл.

# 2. Что сделано?

## Архитектурно

- Переход с Java на Python (так как библиотеки для создания ботов в Python считаются лучше и Python сейчас для меня более актуален).
- Переход с SQLite на PostgreSQL.
- Использован Docker Compose (потому что это удобно, и я не знаю, как запускать postgres без докер-контейнера).
- Добавлена модель пользователя и переосмыслены остальные модели.

## Функционально

- Исправлен вывод таблиц (это уже не таблицы).
- Добавлена возможность смотреть все воркаут-сессии.
- Добавлена возможность посмотреть все упражнения и добавить свои.
- Добавлены пометки к воркаут-сессии (например, если используется периодизация нагрузки, то какая сейчас неделя).

# Модели БД

## users

- id BIGINT (telegram user id)
- ask_workout_date BOOLEAN -- спрашивать дату при завершении тренировки (иначе сегодня)
- ask_workout_notes BOOLEAN -- спрашивать заметку к тренировке
- exercise_log_size SMALLINT -- сколько прошлых тренировок показывать при выборе упражнения, 0 — не показывать
- utc_offset SMALLINT -- часовой пояс: минуты от UTC (180 — Москва)
- ai_wishes TEXT nullable -- последние пожелания для ИИ из `/export`

## exercises

- id SERIAL PK
- name VARCHAR(128)
- user_id BIGINT FK → users.id -- кастомные упражнения пользователя (видит только этот пользователь)

## muscles

- id SERIAL PK
- name VARCHAR(64) -- "грудь", "трицепс", "квадрицепс"
- user_id BIGINT FK → users.id -- кастомные мышцы пользователя (видит только этот пользователь)

## exercise_muscles -- many-to-many

- exercise_id INT FK → exercises.id
- muscle_id INT FK → muscles.id

## workouts

- id SERIAL PK
- user_id BIGINT FK → users.id
- date DATE
- notes TEXT nullable
- start_time TIME nullable -- начало по часам пользователя, до минуты
- end_time TIME nullable -- конец; заполнены оба или ни одного
- program_day VARCHAR(32) nullable -- день программы, по которому записана тренировка
- program_week SMALLINT nullable -- неделя программы; правка тренировки ни день, ни неделю не трогает

## workout_exercises -- какие упражнения были на тренировке

- id SERIAL PK
- workout_id INT FK → workouts.id
- exercise_id INT FK → exercises.id
- position SMALLINT -- порядок упражнений в тренировке
- notes TEXT nullable -- заметка к упражнению в этой тренировке

## sets -- конкретный подход

- id SERIAL PK
- workout_exercise_id INT FK → workout_exercises.id
- reps SMALLINT nullable -- количество повторений
- seconds SMALLINT nullable -- время подхода (планка, farmer's walk); заполнено ровно одно из reps / seconds
- weight NUMERIC(5,2) nullable -- NULL = bodyweight

## programs -- программа тренировок, одна на пользователя

- id SERIAL PK
- user_id BIGINT FK → users.id UNIQUE
- weeks SMALLINT -- длина программы в неделях
- imported_at TIMESTAMPTZ -- момент импорта: с него начинается период экспорта `Current program`

## program_days

- id SERIAL PK
- program_id INT FK → programs.id ON DELETE CASCADE
- position SMALLINT -- порядок дней в неделе
- name VARCHAR(32) -- «Push», «Full Body A»

## program_exercises

- id SERIAL PK
- day_id INT FK → program_days.id ON DELETE CASCADE
- position SMALLINT
- exercise_id INT FK → exercises.id nullable ON DELETE SET NULL -- NULL: упражнение удалили из каталога
- exercise_name VARCHAR(128) -- название из каталога на момент импорта
- notes TEXT nullable -- подсказка ИИ: отдых, техника; в тренировку не пишется

## program_sets -- плановые подходы

- id SERIAL PK
- program_exercise_id INT FK → program_exercises.id ON DELETE CASCADE
- week SMALLINT -- неделя; нет подходов на неделе — упражнения на ней нет
- position SMALLINT
- weight NUMERIC(5,2) nullable, reps SMALLINT nullable, seconds SMALLINT nullable -- как в sets

## program_sessions -- сделанные и пропущенные дни программы

- id SERIAL PK
- program_id INT FK → programs.id ON DELETE CASCADE
- week SMALLINT, day_position SMALLINT -- сессия: день конкретной недели; UNIQUE с program_id
- skipped BOOLEAN -- пропущена кнопкой `Skip`, а не сделана

# Функции бота

## 0. /start

- Мини-инструкция: цикл «тренируешься → `/export` → файл в ИИ → блок `# PROGRAM` обратно в бота → тренировки по плану неделя за неделей → в конце программы снова `/export`», затем список команд.
- Меню команд Telegram задаётся в BotFather, не в коде: `/program` туда нужно добавить вручную.

## 1. /exercises — Упражнения

- Вывести все упражнения.
- Найти упражнение по частичному совпадению названия.
- Отфильтровать по группе мышц.
- Добавить новое упражнение.
- Удалить упражнение, добавленное пользователем.

## 2. /history — История тренировок

- Вывести список тренировок с датами.
- При выборе тренировки — показать упражнения, подходы и заметки (детализация по нажатию / пагинация), время начала и конца и длительность.
- Если включён Mini App (`[history]` в `settings.toml`), вместо списка — кнопка `Open history`, а кнопка меню чата (слева от поля ввода) открывает его сразу: страница со списком тренировок, заметками к упражнениям, графиками прогресса по упражнениям, редактированием и удалением тренировок. В тренировке — время начала и конца и длительность, в списке — длительность; при правке время можно поменять или стереть (тренировка — не дольше 6 часов).

**Mini App локально** (`[db] url` — `localhost:5430`, токен любой):

```bash
docker compose up -d db
uv run alembic upgrade head && uv run -m bot.data.seed
uv run -m history_web.dev_seed 1   # тестовые тренировки для user_id 1, у части — время
uv run -m history_web              # http://localhost:8080
uv run -m history_web.dev_link 1   # ссылка с подписанной initData для браузера
```

**Mini App на сервере:** `history-web` слушает `127.0.0.1:8084`, HTTPS делает nginx сервера (сайт с `proxy_pass http://127.0.0.1:8084` + сертификат через certbot), A-запись домена на сервер, `webapp_url` в `[history]`.

## 3. /workout — Запись тренировки

**Старт:**

- Без программы — сразу окно тренировки с кнопками `Add exercise` и `Finish session`.
- С программой — сначала экран недели: `Week 2 of 4 · Next up: Pull`, кнопки `▶ Start Pull` (первый несделанный день недели), остальные несделанные дни этой недели, `Skip Pull` и `Free workout` (обычная тренировка без плана). На последней неделе сверху строка `Last week of the program — /export after it.`
- Программа пройдена — `/workout` пишет `Program finished — /export your log to get the next one.` и открывает обычную тренировку.
- Окно тренировки показывает, сколько прошло с начала: `Current workout · 45 min`. Время пересчитывается, когда окно рисуется заново — после упражнения, `Back`, `No`; само по себе не тикает.

**Добавление упражнения:**

1. Пользователь вводит название — при частичном вводе выводятся совпадения.
2. После выбора упражнения выводится лог предыдущих результатов (подходы этого упражнения с последних тренировок, где оно встречалось: по умолчанию 10, меняется в `/settings`)
3. Бот ждёт ввода подходов в формате `100x5` (вес × повторения) или `BWx10` (bodyweight). Подход на время — `BWx1:30` или `20x45s` (мин:сек или секунды). При неправильном вводе, пользователю напоминают правильный способ ввода. Русские `х` и `с` (секунды) и запятая тоже подходят: `82,5х5`, `BWх45с`.
4. Текст со словами (не подход) — заметка к упражнению: показывается под названием, новый текст заменяет её, кнопка `Remove note` убирает.
5. После каждого подхода появляется кнопка `Finish exercise` — можно продолжить ввод или завершить.
6. После завершения упражнения снова появляются кнопки `Add exercise` и `Finish session`.

**Тренировка по дню программы:**

- Окно тренировки показывает план дня: `✓` — сделано, `—` — ещё нет, `(deleted)` — упражнение удалили из каталога. Над обычными кнопками — кнопки несделанных упражнений плана, порядок любой.
- Экран упражнения из плана: строка `Plan: 100x5, 100x5`, подсказка ИИ (`Tip:`), если есть, и кнопки плановых подходов. Тап — подход сделан как написано (`✓`), повторный тап снимает отметку. Сделал иначе — вводишь подход текстом, как обычно (`95x5`); текст со словами — заметка.
- Неотмеченные подходы в тренировку не попадают. `Finish exercise` без подходов — пропуск: упражнение не записывается, его кнопка остаётся.
- `Add exercise` добавляет упражнение не из плана.
- План копируется в тренировку при старте: замена или удаление программы на начатую тренировку не влияет.
- В план попадают подходы текущей недели; упражнение, которого на этой неделе нет (`-`), не показывается.
- После сохранения день отмечается сделанным. Неделя сменяется, когда все её дни сделаны или пропущены (`Skip`): пропустил зал — программа ждёт. После последнего дня бот пишет, что программа пройдена. Если программу заменили, пока шла тренировка, отметка в новую не попадает.

**Завершение тренировки:**

1. Бот спрашивает дату — сегодня или ввести вручную. Если в `/settings` дата — `today`, шага нет.
2. Бот спрашивает заметки — добавить или пропустить. Если в `/settings` заметка — `off`, шага нет.
3. Подтверждение — когда есть что проверить: заметка или дата, введённая вручную. Если оба шага выключены, `Finish session` спрашивает yes/no прямо в окне тренировки.
4. Данные сохраняются в БД одной транзакцией (atomic commit), бот отвечает `Workout saved: DD-MM-YY · HH:MM–HH:MM (1 h 15 min).`

**Время тренировки:** начало — `/workout`, конец — последнее нажатие `Finish session`, по часовому поясу из `/settings`. Время не записывается, если дата тренировки — не день начала и не день конца (ввели вручную), если тренировка шла дольше 6 часов (её, скорее всего, забыли закончить) или если её начали до обновления бота. `Today` и `Yes` ставят день нажатия `Finish session`, даже если их нажали уже после полуночи.

**Поведение в особых случаях:**

- **Отмена:** можно отменить текущее упражнение или всю тренировку.
- **Защита от дублей:** повторный `/workout` во время активной записи триггерит предупреждение, что тренировка уже идёт.
- **Асинхронность работы:** доступ к `/exercises` и `/sessions` во время тренировки работает штатно. Состояние текущей тренировки удерживается в FSM и продолжается после использования других команд.

## 4. /settings — Настройки

- `Workout date`: спрашивать дату при завершении тренировки или всегда ставить сегодняшнюю.
- `Workout notes`: спрашивать заметку к тренировке или нет.
- `Exercise log`: сколько прошлых тренировок показывать при выборе упражнения — 10, 5, 3 или не показывать.
- `Time zone`: часовой пояс, по умолчанию UTC+3. Кнопка открывает текущее время во всех поясах — нажимаешь то, что на твоих часах. От пояса зависят «сегодня» и время тренировки.
- Остальные кнопки меняют значение на месте. Всё работает и посреди тренировки, новое значение действует со следующего шага.

## 5. /export — Экспорт для ИИ

1. Период: `Current program` (с даты импорта текущей программы; кнопка есть, только если программа загружена), месяц, 3 месяца, полгода, всё время.
2. Пожелания для ИИ (до 1000 символов): full body, нет тренажёра, шаг блинов 2.5 кг, болит плечо. Бот их запоминает и в следующий раз предлагает `Keep previous`; `Skip` стирает.
3. Файл с промптом: лог тренировок с днём и неделей программы (`| day: Pull (week 2)`), каталог упражнений с мышцами, текущая программа с прогрессом (`Progress: Week 2 of 4 · 5 of 12 sessions done`), пожелания. ИИ анализирует прогресс, сравнивает план и факт и заканчивает ответ блоком `# PROGRAM` в строгом формате (описание формата — `FORMAT_DESCRIPTION` в `bot/programs/parser.py`).

## 6. Программа

**Импорт:** сообщение или `.txt`-файл (до 64 КБ, UTF-8), начинающиеся с `# PROGRAM`, в любой момент, кроме ввода во время тренировки. Отдельной команды нет.

```
# PROGRAM
== Push ==
Bench Press: 100x5x3 / 102.5x5x3 / 105x5x3 / 90x5x2 | notes: rest 3 min
Dips: BWx10x3 / BWx12x3 / BWx12x4 / -
Plank: BWx1:00, BWx1:30 / BWx1:30x2 / BWx1:45x2 / BWx1:00
== Pull ==
Pull-ups: BWx6x3 / BWx7x3 / BWx8x3 / BWx5x2
```

- Программа — дни × недели: структура дня одна, цифры у каждого упражнения на каждую неделю через `/`. `100x5x3` — три подхода по 100×5, через запятую — разные подходы, `-` — упражнения на этой неделе нет. Число недель у всех упражнений одинаковое — это длина программы. Старый формат без `/` — программа на одну неделю.
- Ошибка в любой строке отклоняет весь импорт с номером строки и причиной: `line 7: can't parse set "100x8-12"`, `line 4: "Dips" has 3 weeks, the program has 4`. Только точные цифры, без диапазонов. До 12 недель, 10 дней, 12 упражнений в дне, 10 подходов в упражнении на неделю.
- Сообщение длиннее 4000 символов не принимается — Telegram мог разрезать его на части; такую программу присылают файлом.
- Названия сравниваются с каталогом без учёта регистра. По каждому несовпавшему бот спрашивает: похожие из каталога, поиск текстом или `Create new` (с мышцами, как в `/exercises`). В программу пишется название из каталога.
- Сводка `Program: 4 weeks, 2 days — Push (3), Pull (1).` и `Save program` или, если программа уже есть, `Replace current program`. Новая программа заменяет старую и начинается с первой недели.

**/program:** прогресс (`Week 2 of 4 · 5 of 12 sessions done, 1 skipped` или `Finished · …`), текущая программа в формате импорта (длинная — файлом `program.txt`) и `Delete program`. Удаление нужно, чтобы вернуться к тренировкам без плана; для смены программы достаточно нового импорта.

# Рассылка

Сообщение всем пользователям бота, например анонс обновления. На сервере:

```bash
cd ~/workout-tracker
docker compose -f docker-compose.prod.yaml exec bot python -m bot.broadcast "Текст сообщения"
```

Скрипт покажет текст и число получателей и спросит подтверждение (`y`). Тех, кто заблокировал бота или удалил аккаунт, пропускает. Текст — обычный, без форматирования, до 4096 символов; кавычки можно закрыть на следующей строке, чтобы сообщение было в несколько строк.

# Откат

`migrations` при каждом деплое делает `alembic upgrade head`, а старый образ не знает новых ревизий и падает (`Can't locate revision`). `alembic downgrade` не нужен — он удаляет колонки вместе с данными. Вместо него, на сервере в `~/workout-tracker`:

1. Пока стоит новый образ — отметить в базе последнюю ревизию старого (`down_revision` первой новой миграции). Колонки и данные остаются:

   ```bash
   docker compose -f docker-compose.prod.yaml run --rm migrations alembic stamp <ревизия>
   ```

   Откат к образу до программы тренировок — `ca76cb4f8c6d`: таблицы программ и колонки `workouts.program_day`, `workouts.program_week`, `users.ai_wishes` старому образу не мешают.

2. Задеплоить старый образ. В образах до multi-stage нет `python` из venv в `PATH` — для них в `docker-compose.prod.yaml` вернуть команды через `uv run` (`uv run alembic upgrade head`, `uv run -m bot.data.seed`, `uv run -m history_web`).
3. Когда новый образ выкатится снова, его `migrations` упадёт: колонки уже есть. Вернуть отметку и поднять сервисы:

   ```bash
   docker compose -f docker-compose.prod.yaml run --rm migrations alembic stamp head
   docker compose -f docker-compose.prod.yaml up -d
   ```
